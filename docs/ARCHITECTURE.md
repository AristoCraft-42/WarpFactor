# Flowworks — архитектура

2D-песочница про автоматизированное производство (по мотивам Mindustry, без боевой составляющей).
Godot 4.7.2, GDScript со статической типизацией, только 2D.

## Принятые решения

| Тема | Решение |
|---|---|
| Движок | Godot 4.7.2 (Steam), рендер GL Compatibility |
| Мир | Уровни создаются заранее вручную (файлы `.fwmap`), генерации и сидов в игре нет. Карта конечная, чанки 32×32 — для отрисовки и пространственного поиска |
| Редактор уровней | Внутриигровой, после всех этапов. До него тестовые карты собирает `tools/build_test_levels.gd` |
| Прогрессия | Своя на каждом уровне: стартовые здания, пороги разблокировок, контракты. Цели уровня открывают следующий |
| Песочница | Галочка при запуске уровня: бесплатное строительство, всё открыто, цели не засчитываются |
| Стоимость | Здания стоят ресурсов из ядра, при сносе — возврат 100% |
| Лимит ядра | Излишек принимается и сжигается, но засчитывается как доставка |
| Снос с содержимым | Содержимое (буферы, предметы на лентах) уходит в ядро и засчитывается как доставка |
| Топливо | Нет. Уголь — обычный ингредиент (Silicon Smelter: песок ×2 + уголь ×1). Электричество — после всех этапов |
| Дроблёная порода | Залежь камня → бур → Pulverizer → дроблёная порода → Separator |
| Конвейеры | Модель «слот + прогресс» на тайл (как в Mindustry), хранение SoA, сон/пробуждение |
| Графика | Процедурные плейсхолдеры; спрайты из Aseprite подменяются через поля `sprite`/`texture`/`icon` в `.tres` |
| UI | Собирается кодом, тема Gruvbox (`ui/ui_theme.gd`), RU/EN через `i18n/strings.csv` |

## Структура

```
core/          константы, реестр данных, сетка мира, менеджер зданий, камера, настройки, сессия
buildings/     Building (база), BuildingDef, defs/*.tres
items/         ItemType, ItemStack, types/*.tres (далее — рецепты)
world/         FloorDef, OreDef, LevelDef, LevelMap, LevelIO, floors/, ores/
levels/        LevelDef-файлы кампании и maps/*.fwmap
render/        графика: атласы, плейсхолдеры, террейн, слои зданий, оверлеи, превью
ui/            тема, HUD, меню (главное, пауза, выбор уровня, настройки), инструменты
i18n/          таблица переводов
tests/         тестовая сцена, автопрогон со скриншотами, стресс-тест отрисовки
tools/         dev-скрипты
save/          сериализация сохранений (этап 6)
progression/   разблокировки, контракты, цели (этап 5)
```

## Слои

**Данные** (`Resource` в `.tres`): `ItemType`, `FloorDef`, `OreDef`, `BuildingDef`, `LevelDef`.
`Registry` загружает их из фиксированных папок, сортирует и назначает плотные int-индексы.
В симуляции предметы, полы и руды — только индексы.

**Модель** (без нод):
- `GameWorld` — сетка + здания + параметры сессии.
- `WorldGrid` — плоские `PackedByteArray`/`PackedInt32Array`: пол, руда, id здания на тайл.
- `BuildingManager` — проверка размещения (`OK/REPLACE/SAME/OUT_OF_BOUNDS/BAD_TERRAIN/OCCUPIED`),
  установка, снос, поиск по тайлу и рамке через списки зданий по чанкам. Сигналы `building_added/removed`.
- `Building` — `RefCounted`, не нода. Хуки: `on_placed`, `on_removed`, `get_config/set_config`.

**Представление** (ноды, подписаны на сигналы модели):
- `TerrainView` — два `TileMapLayer`, чанки заполняются лениво с бюджетом времени на кадр;
  под ними обзорная текстура (1 тексель = 1 тайл), при масштабе < 0.3 заменяет тайлмапы (LOD).
- `BuildingLayer` — одна нода `BuildingChunkView` на чанк, перерисовка только грязных чанков.
  Все спрайты зданий лежат в одном атласе, поэтому здания батчатся.
- `GridOverlay` — сетка одним прямоугольником с шейдером; `OreOverlay` — карта ресурсов одной текстурой.
- `PlacementPreview` — призраки, рамка сноса, подсветка.

**Ввод**: `CameraController` (панорама, зум к курсору, края экрана, компенсация масштаба UI),
`ToolController` (строительство, протягивание, снос, пипетка, отмена). Позиция курсора берётся
из событий ввода, а не из системного курсора.

**Интерфейс**: `Hud`, `BuildMenu`, `PauseMenu`, `MainMenu`, `LevelSelect`, `SettingsMenu`.
Controls под `CanvasLayer` не наследуют тему окна — корням таких интерфейсов тема назначается явно.

**Автозагрузки**: `Events` (уведомления UI), `Settings` (настройки и привязки клавиш), `Session` (переходы сцен).

## Настройки

Описываются списком `SettingEntry` (BOOL / CHOICE / RANGE). По этому списку строится меню,
выполняются сохранение в `user://settings.cfg` и применение. Привязки клавиш — по физическим кодам
(не зависят от раскладки), формат `key:Ctrl+S` / `mouse:1`.

## Формат карты `.fwmap` (версия 1)

ZSTD-сжатие; magic `FWMP`, u16 версия, размер, таблицы строковых id полов/руд/зданий,
слои пола и руды (w×h байт), список предустановленных зданий. Индексы в файле переназначаются
по id, поэтому новые типы в `.tres` не ломают старые карты.

## Производительность

Проверено `tests/stress_render.gd` на уровне «Разлом» (320×192), Intel Arc iGPU:
6000 зданий — средний кадр 0.9–1.7 мс на любом масштабе, ~50 draw calls.
Главный риск впереди — симуляция лент (этап 2). Меры: SoA-цикл без виртуальных вызовов,
сон пустых и забитых лент, при необходимости — обновление лент через тик или перенос
`ConveyorSystem` в GDExtension за тем же интерфейсом.

## План этапов

1. ✅ Сетка, камера, уровни из файлов, размещение и снос, главное меню, настройки, RU/EN.
2. Тик симуляции, конвейеры, буры, ядро, стоимость строительства, рендер предметов, пауза и скорость.
3. Логистика: перекрёсток, делитель, сортировщик, мост, шлюзы, разгрузчик, оверлей загрузки лент.
4. Производство: рецепты из данных (`Consume`/`Produce`), заводы, статусы, тултипы.
5. Хранилища, разблокировки и контракты уровня, цели и открытие уровней, HUD со статистикой.
6. Сохранения, оптимизация, полировка.
7. Внутриигровой редактор уровней.
8. Электричество (`ConsumePower` + фаза `PowerGraphSystem`).
