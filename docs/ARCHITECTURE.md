# Flowworks — архитектура

2D-игра про автоматизированное производство, выживание и оборону мобильной базы. Godot 4.7.2,
GDScript со статической типизацией, только 2D.

> С 2026-09-14 цели игры изменены: см. `docs/GDD.md` (дизайн) и `docs/ROADMAP.md` (новый план этапов).
> Этапы 1–4 ниже описывают фабричное ядро, которое переносится без изменений. Решения, помеченные ⚠,
> пересматриваются по новому плану.

## Принятые решения

| Тема | Решение |
|---|---|
| Движок | Godot 4.7.2 (Steam), рендер GL Compatibility |
| Мир ⚠ | Уровни создаются заранее вручную (файлы `.fwmap`), генерации и сидов в игре нет. Карта конечная, чанки 32×32 — для отрисовки и пространственного поиска |
| Редактор уровней ⚠ | Внутриигровой, после всех этапов. До него тестовые карты собирает `tools/build_test_levels.gd` |
| Прогрессия ⚠ | Своя на каждом уровне: стартовые здания, пороги разблокировок, контракты. Цели уровня открывают следующий |
| Творческий режим | Галочка при запуске уровня: постройки не расходуются, радиус дрона не ограничен |
| Игрок | Дрон: WASD, камера следует за ним, действия в радиусе 10 тайлов, медленная добыча руды |
| Хранение | Ядра нет. Предметы лежат в складах и инвентаре дрона: ячейки со стаками, как в Factorio |
| Стоимость | Постройка — предмет: крафтится руками (очередь со временем), ставится из инвентаря, при сносе возвращается |
| Снос с содержимым | Содержимое уходит в инвентарь дрона; что не поместилось — теряется (с уведомлением) |
| Топливо | Нет. Уголь — обычный ингредиент (Silicon Smelter: песок ×2 + уголь ×1). Электричество — этап 11 по `ROADMAP.md` |
| Дроблёная порода | Залежь камня → бур → Pulverizer → дроблёная порода → Separator |
| Конвейеры | Модель «слот + прогресс» на тайл (как в Mindustry), хранение SoA, сон/пробуждение |
| Графика | Процедурные плейсхолдеры; спрайты из Aseprite подменяются через поля `sprite`/`texture`/`icon` в `.tres` |
| UI | Собирается кодом, тема Gruvbox (`ui/ui_theme.gd`), RU/EN через `i18n/strings.csv` |

## Структура

```

               камера, настройки, сессия

               storage/ (склады), gateway/ (центральный шлюз и пара), defs/*.tres
items/         ItemType, ItemStack, Inventory, HandRecipe, Recipe, Consume/Produce и наследники,
               types/*.tres (ресурсы), types/buildings/*.tres (предметы-постройки), recipes/*.tres
player/        DroneDef, Drone, CraftQueue, drone.tres
world/         FloorDef, OreDef, LevelDef, BaseDef (base.tres), LevelMap, LevelIO, floors/, ores/
levels/        LevelDef-файлы кампании и maps/*.fwmap

```

## Слои

**Данные** (`Resource` в `.tres`): `ItemType`, `FloorDef`, `OreDef`, `BuildingDef`, `LevelDef`, `DroneDef`.
`Registry` загружает их из фиксированных папок, сортирует и назначает плотные int-индексы.
В симуляции предметы, полы и руды — только индексы.

**Модель** (без нод):
- `GameWorld` — сетка, здания, симуляция, дрон; все действия игрока (стройка, снос, поворот, перенос предметов)
  с проверкой радиуса дрона и наличия постройки в инвентаре.
- `WorldGrid` — плоские `PackedByteArray`/`PackedInt32Array`: пол, руда, id здания на тайл.
- `BuildingManager` — проверка размещения (`OK/REPLACE/SAME/OUT_OF_BOUNDS/BAD_TERRAIN/OCCUPIED/NO_ORE`,
  `NO_ITEM`/`OUT_OF_RANGE` добавляет `GameWorld`), установка, поворот, снос, поиск по тайлу и рамке через списки
  зданий по чанкам. Сигналы `building_added/removed/rotated`.
- `Building` — `RefCounted`, не нода. Хуки: `on_placed`, `on_removed`, `on_rotated`, `on_proximity_changed`,
  `update_tick`, `accept_item/handle_item`, `collect_contents`, `get_info_lines`, `get_config/set_config`.
  Любое здание можно повернуть; спрайты рисуются «вправо».

**Представление** (ноды, подписаны на сигналы модели):
- `TerrainView` — два `TileMapLayer`, чанки заполняются лениво с бюджетом времени на кадр;
  под ними обзорная текстура (1 тексель = 1 тайл), при масштабе < 0.3 заменяет тайлмапы (LOD).
- `BuildingLayer` — одна нода `BuildingChunkView` на чанк, перерисовка только грязных чанков.
  Все спрайты зданий лежат в одном атласе, поэтому здания батчатся.
- `GridOverlay` — сетка одним прямоугольником с шейдером; `OreOverlay` — карта ресурсов одной текстурой.
- `PlacementPreview` — призраки, рамка сноса, подсветка.

**Ввод**: `CameraController` (следует за дроном, СКМ временно смещает взгляд, зум к курсору, компенсация
масштаба UI), `DroneController` (WASD → направление полёта),
`ToolController`: строительство и протягивание (ЛКМ), выделение области (ПКМ с зажатием) со сносом (X)
и копированием в план (C → вставка ЛКМ, поворот R), пипетка, настройка зданий, добыча руды (ЛКМ по руде). Позиция курсора берётся
из событий ввода, а не из системного курсора. Схема управления версионирована (`InputActions.BINDINGS_VERSION`):
сохранённые привязки старой схемы сбрасываются.

**Интерфейс**: `Hud`, `BuildMenu` (только вкладки и кнопки, описание в подсказке), `InventoryWindow` (инвентарь + крафт или содержимое здания), `CraftQueuePanel`,
`ItemSlot`, `PauseMenu`, `MainMenu`, `LevelSelect`, `SettingsMenu`.
Controls под `CanvasLayer` не наследуют тему окна — корням таких интерфейсов тема назначается явно.

**Автозагрузки**: `Events` (уведомления UI), `Settings` (настройки и привязки клавиш), `Session` (переходы сцен).

## Настройки

Описываются списком `SettingEntry` (BOOL / CHOICE / RANGE). По этому списку строится меню,
выполняются сохранение в `user://settings.cfg` и применение. Привязки клавиш — по физическим кодам
(не зависят от раскладки), формат `key:Ctrl+S` / `mouse:1`.

## Формат карты `.fwmap` (версия 1)

ZSTD-сжатие; magic `FWMP`, u16 версия, размер, таблицы строковых id полов/руд/зданий,
слои пола и руды (w×h байт), список предустановленных зданий. Индексы в файле переназначаются
по id, поэтому новые типы в `.tres` не ломают старые карты.

## Симуляция (этап 2)

**Такт.** `SimClock` накапливает время кадра и выполняет фиксированные тики `Simulation.step()`
(30 в секунду; ×2/×4 — больше тиков той же длины, не больше 8 за кадр). `alpha` — доля до следующего
тика, используется только отрисовкой. Меню паузы блокирует часы.

**Тик.** Планировщик (`Scheduler`, timing wheel) будит здания, чьё время пришло → `ConveyorSystem`
двигает бодрствующие ленты → бодрствующие здания выполняют `update_tick` → статистика.
Разбуженное во время тика здание обновится на следующем — предмет не пройдёт две постройки за тик.

**Сон и пробуждение.** Пустые и заблокированные ленты, бур между предметами, источник без места
не обновляются. Будят их: пришедший предмет, `notify_space` получателя (подписка `add_waiter`),
изменение соседства, планировщик.

**Ленты** (`ConveyorSystem`, SoA): до 3 предметов на тайл, прогресс в целых единицах
(1200 на тайл, зазор 480) — без накопления ошибок float, детерминированно. Передача вперёд
сохраняет перебег, вставка сбоку — на середину тайла. Встречные ленты не передают друг другу.
Ссылки между лентами — по id зданий (индексы меняются при удалении).

**Передача предметов**: `accept_item` / `handle_item`, `dump` — по кругу соседям (`proximity`).

**Экономика.** `GameWorld.build/demolish/rotate_building`: стоимость списывается из `CoreStorage`,
при сносе возвращается; содержимое снесённого здания уходит в ядро как доставка. Ядро сжигает
излишек сверх лимита, но засчитывает его. `ItemStats` — скользящее окно +/− в секунду.

**Отрисовка предметов**: один `MultiMeshInstance2D`, иконки в атласе-полосе (шейдер выбирает ячейку
по `INSTANCE_CUSTOM`), позиция интерполируется между тиками, только видимые чанки, LOD при масштабе < 0.4.

## Логистика (этап 3)

| Здание | Класс | Поведение |
|---|---|---|
| Перекрёсток | `Junction` | Очередь на каждое направление (6 предметов), выход на противоположную сторону не раньше 8 тиков |
| Делитель | `Router` | Буфер на 1 предмет, отдаёт по кругу любому соседу, кроме источника |
| Сортировщик | `Sorter` | Мгновенно: выбранный предмет вперёд, остальные в стороны; инверсия (настройка) — наоборот |
| Переливной клапан | `OverflowGate` | Мгновенно: вперёд, иначе в стороны; обратный режим (настройка) — в стороны, иначе вперёд |
| Мостовой конвейер | `BridgeConveyor` | Связь со следующим мостом до 4 тайлов по прямой, буфер 10; конец цепочки отдаёт соседям, но не назад |
| Разгрузчик | `Unloader` | Берёт из соседних складов, готовой продукции заводов и буфера буров (по фильтру или по очереди) и отдаёт соседям; из склада в склад и назад в источник не кладёт |

- **Уровни и пропускная способность.** У каждого логистического здания есть титановая версия.
  `LogisticDef.throughput_of` ссылается на ленту своего уровня: здание пропускает не чаще раза
  в `get_ticks_per_item()` тиков, как эта лента при плотном потоке (обычная — 6, титановая — 10 предм./с).
  Делитель держит предмет на интервал − 1 тик, перекрёсток и мост выдерживают интервал на выходе,
  разгрузчик — между перекладываниями.
- **Мгновенные здания** (`PassThroughBuilding`) не имеют буфера: предмет проходит сквозь них
  внутри `accept_item/handle_item`; «вперёд» — сторона, противоположная источнику. Цепочки ограничены
  глубиной 8. После предмета здание не принимает следующий интервал и просыпается за тик до его конца,
  чтобы разбудить ожидающих (ленты обновляются в тике раньше зданий). Заблокированная лента ждёт
  и само здание, и его соседей.
- **Настройка** (`get_config_kind/get_config/set_config`): фильтр-предмет, инверсия (`supports_inversion`,
  у сортировщика настройка — словарь `{item, inverted}`, у клапана — bool) или смещение до связанного моста.
  Меняется через `GameWorld.configure` (встречная связь мостов снимается), копируется пипеткой,
  применяется при строительстве. Клик пустой рукой выбирает настраиваемое здание; для моста клик по другому
  мосту в дальности связывает их. Протягивание мостов ставит их с шагом дальности и связывает цепочкой.
- **Оверлей загрузки лент** (L): пустые, поток, плотный поток, затор.

## Производство (этап 4)

**Рецепты — данные** (`items/recipes/*.tres`): `Recipe` = список `Consume` + список `Produce` + время цикла.

| Класс | Назначение |
|---|---|
| `Consume` (абстрактный) | `accepts_item`, `item_capacity`, `is_satisfied`, `consume`, `refund`, `efficiency`, `describe_missing` |
| `ConsumeItems` | Предметы из входного буфера |
| `Produce` (абстрактный) | `can_output`, `produce`, `output_items`, `display_stacks/chances` |
| `ProduceItems` | Гарантированный выход |
| `ProduceWeighted` | Случайный выход по весам через RNG мира (детерминирован от id уровня) |

`Crafter` работает только через этот интерфейс: принимает входы рецепта в буфер, в начале цикла списывает их,
спит до конца цикла (`finish_tick`), кладёт результат в выходной буфер и раздаёт соседям по одному предмету
за тик. Статусы: работает / нет сырья (с перечнем) / выход забит. Время цикла делится на минимальную
`efficiency` входов — так в будущем `ConsumePower` замедлит завод при нехватке энергии без правок `Crafter`.

| Завод | Вход | Выход | Цикл |
|---|---|---|---|
| Дробилка | камень ×1 | дроблёная порода ×1 | 0.7 с |
| Графитовый пресс | уголь ×2 | графит ×1 | 1.5 с |
| Кремниевый завод | песок ×2 + уголь ×1 | кремний ×1 | 0.7 с |
| Печь | песок ×1 + свинец ×1 | металлостекло ×1 | 0.5 с |
| Сепаратор | дроблёная порода ×2 | медь 5 / свинец 3 / уголь 2 / титан 2 (веса) | 0.6 с |
| Смеситель сплава | медь ×3 + свинец ×4 + титан ×2 | сплав ×1 | 1.5 с |

**Подсказка у курсора** (`BuildingTooltip`): название, рецепт иконками с шансами и временем, статус цветом,
прогресс цикла, буферы. Характеристики заводов показываются и в меню строительства.

## Дрон, инвентарь и крафт (этап 5)

**Предметы-постройки.** У каждой строящейся постройки есть `ItemType` с полем `building`
(`items/types/buildings/`). Здание хранит индекс своего предмета (`item_index`), а не ссылку —
иначе ресурсы образовали бы цикл и не освобождались. Постройки ездят по лентам и лежат в складах
как обычные предметы.

**`Inventory`** — ячейки (предмет + количество до `stack_size`). Суммы и число ячеек по каждому
предмету кэшируются, поэтому `space_for` — O(1): склад, который лента проверяет каждый тик, не
сканирует ячейки. У дрона инвентарь автосортируемый. `Inventory.Budget` — копия количеств для
планирования ряда построек.

**`StorageBuilding`** (контейнер 16 ячеек, хранилище 48) принимает предметы, пока есть место. Когда место
освобождается (разгрузчик или игрок забрали предмет), будит ленты через `notify_space`.

**`Drone`** — модель в тике симуляции (после зданий): движение с интерполяцией отрисовки, радиус действий
`can_reach_*`, добыча руды (`mine_ticks = база + твёрдость × коэффициент`, уровень руды ≤ `mine_tier`),
очередь крафта.

**`CraftQueue`** — очередь единиц. Единица — полный план одного крафта: недостающие промежуточные детали
(например, лента для титановой ленты) докрафчиваются в той же единице. Сырьё списывается при постановке
и полностью возвращается при отмене. Результат выдаётся по окончании; при полном инвентаре очередь ждёт.
Рецепты (`HandRecipe`) строит реестр из `BuildingDef.cost`, `craft_time`, `craft_amount`.

**Действия игрока** (`GameWorld`): `check_build`/`build` (радиус, предмет в инвентаре; при замене сначала
снос старого с возвратом), `demolish` (радиус, место под постройку; `last_error`, `last_lost_items`),
`rotate_building`, `player_take`/`player_put` (окно здания). Интерфейс здания для окна:
`has_player_window`, `get_inventory`, `accepts_player_items`, `get_player_stacks`, `take_player_items`.

## База и планета (этап 6)

**`Run`** (забег) владеет двумя `GameWorld` — планетой (карта уровня) и базой (`BaseDef`: пустое
пространство 24×24 из металлических плит), общим дроном и `GatewayLink`. `SimClock` вызывает `Run.step()`:
обе симуляции тикают всегда, какой бы мир ни был на экране. Дрон обновляется в симуляции того мира,
где находится (`drone.world`); действовать (строить, сносить, настраивать, брать предметы) можно только
там (`GameWorld.has_drone`).

**Центральный шлюз и пара** (`GatewayBuilding`, `GatewayDef`): шлюз 3×3 ставится на планете на место
посадки, пара — в центр базы. Портов два, стороны зеркальные: предмет, вошедший в западный порт шлюза,
выходит из западного порта пары; вошедший в восточный порт пары — выходит из восточного порта шлюза.
Между мирами — две очереди `GatewayLink` (по 10 предметов); выдача ограничена пропускной способностью
обычной ленты. Порт принимает предмет только от здания, стоящего на тайле порта. Когда очередь
освобождается, шлюз будит ленты у входа на другой стороне (`notify_space` в чужом мире).

**Переход дрона**: над шлюзом (или парой) HUD показывает «F — войти в базу / выйти на планету»;
`Run.use_gateway` переносит дрона в ту же точку другой стороны и шлёт `drone_changed_world`.

**Площадка**: `GameWorld.pad_rect` — 15×15 вокруг шлюза, рисуется пунктиром (`PadOverlay`), в инфо-панели
помечена. Переезд площадки при телепорте — этап 7.

**Представление** (`WorldView`): у каждого мира свои террейн, сетка, граница, здания, предметы, оверлеи,
площадка. Неактивный вид скрыт и заморожен (`PROCESS_MODE_DISABLED`), изменения зданий копятся грязными
чанками. При переходе `Game` меняет активный вид и переключает на новый мир инструменты (`ToolController.set_world`),
камеру (границы карты) и панели HUD. Свойства `Game.terrain/building_layer/...` отдают активный вид.

## Производительность

Замеры на Intel Arc iGPU:

| Сценарий | Результат |
|---|---|
| Отрисовка: 6000 зданий, 10 тыс. предметов на лентах (`stress_render`) | кадр 1–2 мс на любом масштабе, ~70 draw calls |
| 4000 лент, все в движении, плотный поток (`bench_conveyors`) | 3.8 мс/тик → на ×4 ≈ 7.5 мс/кадр при 60 FPS |
| 4000 лент, все забиты | 0.002 мс/тик (все спят) |
| 100 буров + 4000 лент, реальный поток | 1.2 мс/тик (так же на этапе 4) |

Резервы, если понадобится: обновление лент через тик с двойным шагом, перенос `ConveyorSystem`
