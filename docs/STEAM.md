# Steam: лобби, приглашения и P2P

Совместная игра через Steam — это ещё одна реализация транспорта (`net/steam_transport.gd`)
поверх того же lockstep, что и локальная сеть. Игра без Steam работает как раньше: аддон
необязательный, и если его нет, кнопки Steam просто не показываются.

## Что установлено

| Что | Откуда | Зачем |
|---|---|---|
| `addons/godotsteam/` | [GodotSteam v4.22.1-gde](https://codeberg.org/godotsteam/godotsteam/releases) (официальный репозиторий, лицензия MIT) | Доступ к Steamworks из GDScript: лобби, P2P, друзья |
| `steam_api64.dll` и его аналоги внутри аддона | Steamworks SDK 1.65 от Valve | Библиотека самого Steam, с ней общается GodotSteam |
| `steam_appid.txt` в корне проекта | создан вручную | App ID для запуска не из Steam; `480` — тестовое приложение Valve (Spacewar) |

**Что стоит знать о стороннем коде.** Аддон — нативные библиотеки: они выполняются в том же
процессе, что и игра. Steamworks по своей природе общается с клиентом Steam и серверами Valve
(лобби, P2P-ретрансляция, статистика приложения) — это и есть его работа. Кроме того, в аддоне
есть плагин редактора, который при открытии проекта ходит на `godotengine.org` проверять
обновления; он выключен настройкой `steam/updates/godotsteam/check_for_updates = false`
в `project.godot`. Обновлять аддон лучше вручную, скачивая релиз с официального репозитория.

## Известная проблема: Steam-сборка Godot

Godot, установленный **из Steam**, кладёт рядом с собой свой `steam_api64.dll` — и он старее того,
что нужен GodotSteam. Windows подхватывает ту библиотеку, что уже загружена в процесс, поэтому
аддон не грузится:

```
Can't open dynamic library: .../libgodotsteam.windows.template_debug.x86_64.dll.
Error 127: Не найдена указанная процедура.
```

Проверить версии:

```powershell
(Get-Item 'D:\SteamLibrary\steamapps\common\Godot Engine\steam_api64.dll').VersionInfo.FileVersion
(Get-Item 'D:\Mind\addons\godotsteam\win64\steam_api64.dll').VersionInfo.FileVersion
```

**В этом проекте уже сделано:** библиотека в установке Godot заменена на версию из аддона (10.83.75.46),
старая сохранена рядом как `steam_api64.dll.bak`. Если Steam проверит целостность файлов и вернёт
старую библиотеку, аддон снова перестанет грузиться — просто повторите замену.

Лечится одним из двух способов (это рекомендация самих авторов GodotSteam):

1. **Заменить библиотеку в установке Godot** на версию из аддона (старую сохранить рядом как
   `steam_api64.dll.bak`). Минус: Steam при проверке целостности файлов вернёт старую.
2. **Взять обычную сборку Godot 4.7.2** (не из Steam) для разработки — тогда в процессе нет
   чужой библиотеки и аддон грузится сам.

Пока аддон не загрузился, всё остальное работает: игра идёт, сетевая игра по локальной сети
и прямому адресу доступна, кнопки Steam скрыты.

## Как проверить, что Steam завёлся

```
godot --headless --path D:\Mind res://tests/steam_probe.tscn
```

Печатает, загрузился ли аддон, его версию, App ID и поднялся ли Steam. Ожидаемый вывод, когда
всё на месте и клиент Steam запущен:

```
Аддон GodotSteam загружен: да
Версия GodotSteam: 4.22.1
App ID: 480
Steam запущен: да
Steam ID: 7656119..., имя: ...
```

Если клиент Steam не запущен, последняя строка будет «Steam запущен: нет (Cannot create IPC pipe
to Steam client process...)» — это нормально: аддон работает, не хватает только самого Steam.

Служебный дамп API (какие функции и сигналы есть в установленной версии) — `tests/steam_api_dump.tscn`.

Дальше — в игре: меню паузы → «Открыть через Steam», у друга главное меню → «Подключиться» →
игра появится в списке «Игры в Steam».

## Живая проверка (нужен запущенный Steam)

```
godot --headless --path D:\Mind res://tests/steam_live_check.tscn
```

Создаёт лобби, читает его данные и владельца, запрашивает список лобби и поднимает хост
на Steam-транспорте. Проверено на этой машине: 13 проверок, все зелёные.

Чего эта проверка **не** покрывает: подключение второго игрока — двух аккаунтов Steam в одном
процессе не бывает, это проверяется с двух машин (или с двух аккаунтов).

Замечания, которые видно по её выводу:

- **Своё лобби в списке не появляется** — Steam не возвращает лобби, в котором вы уже состоите.
  Это нормально: список нужен гостю, а не хозяину.
- Поиск ведётся по всему миру (`LOBBY_DISTANCE_FILTER_WORLDWIDE`), иначе Steam показывает только
  свой регион. На тестовом приложении 480 чужих лобби может не быть вовсе — пустой список
  не означает поломку, важно что запрос получает ответ за доли секунды.

## App ID

В настройках игры («Игра» → «App ID в Steam») стоит `480` — тестовое приложение Valve: лобби и P2P
работают без своего релиза в Steam. Когда появится собственный App ID, его достаточно вписать туда
же и обновить `steam_appid.txt`.

## Оверлей Steam и кнопка «Пригласить друзей»

Оверлей (Shift+Tab) — не часть игры: его встраивает в процесс сам Steam, и **только когда игру
запустил Steam**. Из редактора Godot и по двойному клику по exe оверлея нет, поэтому:

- Shift+Tab ничего не открывает;
- окно приглашения друзей (`activateGameOverlayInviteDialog`) не показывается.

`steam_appid.txt` эту ситуацию не чинит: он даёт доступ к API (лобби, P2P, друзья — всё работает),
но не заставляет Steam внедрить оверлей.

**Как получить оверлей при разработке:** Steam → «Добавить игру» → «Добавить стороннюю игру»,
указать exe (или сам Godot с аргументами проекта), и запускать уже из библиотеки Steam.
После релиза под своим App ID оверлей появится сам.

**Что делает игра, когда оверлея нет.** Кнопка «Пригласить друзей» не молчит:
`SteamLobbies.overlay_available()` спрашивает у Steam `isOverlayEnabled()`, и если оверлея нет,
меню паузы показывает подсказку и **кладёт SteamID хоста в буфер обмена** — друг вставляет его
в поле подключения и входит без оверлея. Если игра ещё не открыта через Steam, подсказка другая:
сначала «Открыть через Steam».
